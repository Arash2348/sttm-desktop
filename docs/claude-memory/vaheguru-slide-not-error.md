The user (2026-09-25) does not count time on the Vaheguru slide (app searching during kirtan) as a real negative — faster
re-lock is nice-to-have, not a problem. What matters is wrong shabad/line on screen (false positives).

**Why:** a blank/Vaheguru slide is a safe fallback for the sangat; showing the wrong Bani is the actual failure.

**How to apply:** rank metrics as wrong-shabad seconds / wrong switches first, correct time second, searching time only
as a minor tie-breaker. Never tune for faster lock if it adds any wrong-shabad time. Report searching time neutrally,
not as an error. Related: [[verified-data-home]]
